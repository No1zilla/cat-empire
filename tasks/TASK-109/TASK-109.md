# 📌 TASK-109: Оплаченная покупка могла молча пропасть

> **Статус:** ✅ Исправлено
> **Приоритет:** P0 — потеря оплаченного товара, без следов
> **Зависимости:** [TASK-107](../TASK-107/TASK-107.md)

---

## Как нашли

Смотрели 56 «проглоченных исключений», которые `repowise` пометил как низкий приоритет. Распределение оказалось говорящим:

| Файл | Проглочено | Что здесь ломалось сегодня |
|---|---|---|
| `Game.js` | 7 | TASK-105 |
| `StorageService.js` | 6 | TASK-106, TASK-107 |
| `EventTracker.js` | 6 | TASK-092 |
| `RubyShopModal.js` | 5 | **покупки за деньги** |
| `client.js` | 4 | TASK-097 |

**Каждый баг, найденный за сегодня, жил в файле из этой пятёрки.** И каждый был молчаливым. Проглоченные исключения — не «качество кода», а механизм, которым эта кодовая база прячет собственные отказы.

## Баг

Все три платёжных пути (`RubyShopModal` — паки и указ, `StarterTributeModal` — ларец) выглядели так:

```js
if (this.economy) this.economy.addGems(pack.rubies);  // рубины только в памяти
markOrderProcessed(orderId);                           // заказ сожжён
try { await storageService.persistCurrency({...}); } catch (e) {}  // молча съедено
eventTracker.track('iap_purchase_completed', {...});   // аналитика: успех
UIUtils.showToast(stage, `+${...} на баланс`);         // игроку показан успех
```

Если запись падала, последствия складывались одно к одному:

1. Рубины остались только в памяти — исчезнут при перезагрузке
2. Заказ уже помечен обработанным, `wasOrderProcessed` ответит «зачислено» — **вернуть нельзя**
3. Аналитика отрапортовала успешную покупку — в отчётах ничего не видно
4. Игрок увидел «+50 на баланс» — узнает о пропаже сам, позже

То есть **деньги взяли, товар потеряли, следов не осталось.** Вероятность выросла после [TASK-107](../TASK-107/TASK-107.md): теперь запись идёт в VK Storage, а он может не ответить.

## Исправление

**Порядок изменён: сохранить → и только потом сжигать заказ.** Если запись не удалась, `markOrderProcessed` не вызывается — VK отдаст тот же `orderId`, и начисление можно повторить при следующем заходе.

Во всех трёх путях `catch` больше не пустой:
- в консоль идёт настоящая ошибка;
- в аналитику — новое событие **`iap_grant_failed`** с паком и суммой;
- игроку — «Рубины не сохранились. Открой игру ещё раз» вместо ложного успеха.

Событие зарегистрировано в дашборде как «Оплачено, но не выдано». Раньше такой случай не отличался от обычной покупки; теперь он виден отдельной строкой.

## Проверка

`npm test`, `build:vk`, серверный `test_analytics_and_admin_spec.js` — зелёные.

## Что осталось

Исправлены только денежные пути. Остальные ~50 проглоченных исключений живут в некритичных местах (телеметрия, звук, тактильная отдача), где молчание оправдано — падение аналитики не должно ронять игру. Разбирать их скопом ради метрики смысла нет: ценность не в количестве, а в том, чтобы **отказ в важном пути был слышен**.

Следующий кандидат по тому же принципу — `AdModal` (2 проглоченных): там начисляются рубины за просмотр рекламы, то есть тоже выдача товара, пусть и не за деньги.
