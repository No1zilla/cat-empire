# 📌 TASK-107: Прогресс живёт в VK Storage, сервер убран из критического пути

> **Статус:** ✅ Сделано (VK Storage проверяется только внутри VK — см. «Что осталось»)
> **Приоритет:** P0
> **Зависимости:** [TASK-106](../TASK-106/TASK-106.md)

---

## Зачем

[TASK-106](../TASK-106/TASK-106.md) показал корень потери прогресса: загрузка ждала ответа Railway, из РФ он не укладывался в таймаут, игра сваливалась в стартовую заглушку и **затирала ею настоящую империю** — во всех трёх хранилищах сразу, включая VK Storage, из-за чего обнулялся и телефон.

Тот фикс защитил от затирания, но игра всё равно показывала чистый старт при медленной сети. Решение — убрать Railway из пути загрузки прогресса совсем.

VK Storage для этого подходит лучше по существу: он ходит через инфраструктуру самого ВКонтакте (а не через хостинг без регионов в РФ), привязан к VK-аккаунту и потому **сам по себе даёт кросс-платформенность** между десктопом и телефоном.

## Что изменилось

**Загрузка.** `loadProgress()` больше не зовёт `fetchProfile()`. Читается локальный кэш и VK Storage, дальше обычное слияние по рангу. Ушла и общая гонка на 6 секунд: ждать нечего, у `storageGet` свой таймаут.

**Сохранение.** `saveProgress()` ждёт и проверяет запись в VK Storage (`lastCloudSaveOk`). Копия на сервер уходит **без `await`** и только ради таблицы лидеров, которая ранжирует игроков запросом `FROM users`. Медленный Railway теперь не задерживает игру и не влияет на судьбу сохранения.

**`storageSet` перестал врать.** Возвращал `true` даже по таймауту. Раз VK Storage стал источником правды, вызывающая сторона обязана отличать «записалось» от «не дождались» — теперь возвращает реальный результат.

### Найденная по дороге дыра: рубины мимо VK Storage

Восемь мест писали валюту **прямым вызовом `saveProgress({ gems })` в API**, минуя `storageService`:

| Файл | Что начисляло |
|---|---|
| `RubyShopModal.js` ×2 | **купленные за деньги рубины** |
| `StarterTributeModal.js` | купленный стартовый пак |
| `AdModal.js` ×2 | рубины за рекламу |
| `LiveOpsRow.js` | паёк указа |
| `DesktopRewardModal.js` | награда за приглашение |
| `AutoMergeButton.js` | монеты + рубины после авто-слияния |

Пока источником правды был сервер, это работало. После переезда на VK Storage такие рубины — **включая оплаченные** — не дожили бы до следующей загрузки.

Добавлен `storageService.persistCurrency(patch)`: читает текущий снимок, правит нужные поля и сохраняет обычным путём. Все восемь мест переведены на него, мёртвые импорты убраны. `main.js` оставлен как есть — он шлёт только имя и аватар для лидерборда, это не прогресс.

## Что осталось

- **Сам VK Storage локально не проверить** — он работает только внутри VK Mini App, вне VK `storageGet/storageSet` выходят по короткому таймауту. Проверено, что сервер не нужен; работу VK Storage подтвердит только запуск в реальном VK: купить кота, перезагрузить, затем зайти с телефона под тем же аккаунтом.
- **Таблица лидеров** теперь наполняется копией, которая уходит без гарантий. Если Railway недоступен, лидерборд у такого игрока обновляться не будет — сам прогресс при этом цел. Это осознанный размен.
- **Империя на гостевом `999999999`** (544 млн монет, 12 уровень) по-прежнему не перенесена — это миграция боевых данных, нужно решение владельца.
