## 🎯 Цель
Запустить A/B тесты для проверки гипотез об улучшении монетизации и retention. Делать решения на основе данных, а не интуиции.

## 🧪 Список A/B гипотез для тестирования

### Гипотеза 1: Награда за рекламу (+5 vs +8 гемов)
- **Контрол (A)**: +5 💎 за рекламу (текущее)
- **Тест (B)**: +8 💎 за рекламу
- **Метрика успеха**: Ads per DAU, D7 retention
- **Гипотеза**: Большая награда → больше просмотров рекламы → выше retention

### Гипотеза 2: Стоимость авто-слияния (5 vs 3 гема)
- **Контрол (A)**: 5 💎 за «Соединить» (текущее)
- **Тест (B)**: 3 💎 за «Соединить»
- **Метрика успеха**: `merge_auto_triggered` events per session, ad_requested (нужда в гемах)
- **Гипотеза**: Дешевле → чаще используют → быстрее кончаются гемы → больше рекламы

### Гипотеза 3: Начальный баланс (100 vs 50 монет)
- **Контрол (A)**: 100 монет старт (текущее)
- **Тест (B)**: 50 монет старт + +10 гемов стартовых
- **Метрика успеха**: D1 retention, time_to_first_ad
- **Гипотеза**: Меньше монет → быстрее нужна реклама → раньше привязывается к механике

### Гипотеза 4: Туториал (есть vs нет)
- **Контрол (A)**: Без туториала (текущее)
- **Тест (B)**: 3-шаговый туториал при первом запуске
- **Метрика успеха**: Воронка до первого слияния, D1 retention
- **Гипотеза**: Туториал → более глубокое понимание механик → лучше retention

### Railway API: `GET /ab-tests/active`
Возвращает список активных тестов и их конфигурацию:
```json
{
  "tests": [
    {
      "name": "ad_reward_gems",
      "variants": {
        "A": { "gems": 5 },
        "B": { "gems": 8 }
      },
      "active": true
    }
  ]
}
```

### Анализ результатов A/B теста
```sql
SELECT
  props->>'ab_group' AS ab_group,
  COUNT(DISTINCT user_id) AS users,
  COUNT(*) FILTER (WHERE event = 'ad_completed') AS ad_completions,
  ROUND(AVG((props->>'session_duration')::numeric)) AS avg_session_sec
FROM analytics_events
WHERE props->>'ab_test' = 'ad_reward_gems'
  AND created_at > NOW() - INTERVAL '14 days'
GROUP BY ab_group;
```
