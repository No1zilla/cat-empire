# 📌 TASK-017: Исправление бага списания и сохранения гемов (Gem Persistence Fix)

> **Статус:** 🟡 В очереди
> **Приоритет:** Высокий (Критический баг списания валюты)
> **Зависимости:** TASK-005, TASK-008

---

## 🎯 Диагноз бага (Root Cause)

### Что происходит:
Игрок имеет 10 гемов. Нажимает «Соединить все» (списывается 5 гемов, остается 5). Обновляет страницу — гемов снова 10!

### Причина бага в коде:
1. В `AutoMergeButton.js` при клике за гемы списывается баланс в памяти (`this.economy.gems -= GEM_COST`), **НО вызов `saveProgress()` на серверНЕ выполняется!**
2. В результате на сервере в базе данных остаётся старое значение (`gems: 10`).
3. При перезагрузке страницы вызов `fetchProfile()` загружает с сервера устаревшее значение (10 гемов) и затирает локальное состояние.

---

## 🛠 Задачи для разработчика:

### 1. Добавить сохранение при списании гемов (`AutoMergeButton.js`)
В методе `_handleClick()` после списания гемов вызывать `saveProgress()`:
```javascript
if (this.economy) {
  this.economy.spendGems(GEM_COST); // Списание через метод с вызовом сохранения
  await saveProgress({
    coins: this.economy.coins,
    gems: this.economy.gems,
    totalCatsBought: this.economy.totalCatsBought,
    gridState: this.grid ? this.grid.exportState() : null
  });
}
```

### 2. Добавить `spendGems()` в `Economy.js`
В класс `Economy` добавить валидный метод списания премиум-валюты:
```javascript
spendGems(amount = 0) {
  if (this.gems < amount) {
    throw new Error('Недостаточно гемов');
  }
  this.gems -= Number(amount);
  this._notify();
}
```

### 3. Резервный `localStorage` при сбоях сети (`Game.js`)
При загрузке профиля проверять локальное кешированное значение гемов на случай сетевых сбоев.

---

## ✅ Критерии приёмки
- При нажатии на платный Auto-Merge (5 гемов) баланс снижается с 10 до 5.
- На бэкенд мгновенно уходит HTTP POST `/api/user/save` с новым `gems: 5`.
- При перезагрузке страницы баланс гемов остается равным 5 💎.
