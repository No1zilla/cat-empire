# 📌 TASK-105: Прогресс новичков не сохранялся никогда — самозапирающийся guard, не сеть

> **Статус:** ✅ Исправлено
> **Приоритет:** P0 — прямая причина потери прогресса, не зависит от Railway/VPN/сети
> **Зависимости:** нет

---

## Как нашли

Пользователь в РФ сообщил: `/admin` без VPN не открывается. Проверка сузилась дальше: без VPN купил кота, перезагрузил страницу — прогресс пропал. Это выглядело как прямое подтверждение гипотезы «Railway недоступен из РФ» ([TASK-098](../TASK-098/TASK-098.md)).

Потом решающий факт: **«даже с VPN не сохраняется прогресс».** VPN снимает любые сетевые ограничения на Railway. Если прогресс не сохраняется и с VPN — сеть тут ни при чём. Это баг в клиентском коде, не в маршруте до сервера.

## Воспроизведение

Не гадание по чтению кода — живой Playwright-репро на `localhost` с полным контролем таймингов:

1. Чистый профиль (`localStorage.clear()`)
2. Купить кота через `window.game.spawnSystem._spawnCat()`
3. `location.reload()` с разными задержками — 0мс, 100мс, 500мс, 900мс, 1500мс

**До фикса:** прогресс терялся при **любой** задержке, включая 1500мс — то есть не гонка с 800мс debounce, а полное отсутствие сохранения.

Контрольный тест без reload (просто подождать 2с) показал, что покупка применяется в памяти корректно (`totalCatsBought: 0→1`, монеты списаны) — баг именно в сохранении, не в самой покупке.

## Причина — временные `console.log` в `SyncManager`/`StorageService`/`Game.js` показали точно

```js
// src/game/Game.js, было:
_syncToCloud() {
  if (!this.economy) return;
  const snap = this._getStateSnapshot();
  if (!this._cloudSaveOk && isStarterSnapshot(snap)) return;   // ← самозапирающийся guard
  this._cloudSaveOk = true;
  syncManager.scheduleSave(snap, 800);
}
```

`isStarterSnapshot` — это `totalCatsBought <= 2 && totalMerges <= 0 && maxCatLevel <= 1`. `_cloudSaveOk` стартует `false` для нового игрока. Единственное место, где `_cloudSaveOk` становится `true` — **внутри той же функции, сразу после того же guard**. Пока игрок не купил больше 2 котов и ни разу не слил (то есть весь первый визит в игру) — `isStarterSnapshot(snap)` остаётся `true`, guard возвращает раньше строки `this._cloudSaveOk = true`, и флаг остаётся `false` навсегда. Заперто само на себя.

Тот же паттерн был продублирован в `_bindLifecycleFlushes()` — и на `visibilitychange` (сворачивание/скрытие вкладки), и на `pagehide` (закрытие/уход со страницы). То есть аварийный флаш при закрытии вкладки был заблокирован тем же условием — резервный путь не спасал.

**Итог:** любой новый игрок, который купил 1–2 кота и не слил ни разу (это буквально первая минута игры для многих — самая частая точка, где закрывают вкладку), терял весь прогресс при следующем заходе. Гарантированно, на любом устройстве, без всякой связи с сетью или Railway.

## Почему guard вообще был

Судя по логике `storageService.mergeStates()` (сравнение по `progressRank`, свежий пустой снимок не должен перезатирать облачную империю — это отдельно и корректно защищено рангом на уровне слияния), guard в `_syncToCloud()` был попыткой не слать в сеть заведомо пустой стартовый снимок. Уместно для **разового** сохранения сразу после загрузки (оно и есть отдельной строкой, `if (this._cloudSaveOk) this._saveToLocalStorage();`, не трогали). Но тот же guard оказался скопирован в путь, который срабатывает на **каждое реальное действие игрока** — а действие есть действие, его терять нельзя, и защита от перезаписи облака уже есть на уровне `mergeStates`.

## Фикс

Убран самозапирающийся guard из трёх мест в `src/game/Game.js`: `_syncToCloud()` и оба обработчика в `_bindLifecycleFlushes()` (`visibilitychange` и `pagehide`). Разовое сохранение сразу после загрузки (`if (this._cloudSaveOk) ...` вне этих трёх мест) не тронуто — оно не самозапирающееся, `_cloudSaveOk` там выставляется один раз при `init()` по загруженному прогрессу.

## Связь с TASK-098 (Railway/РФ)

Это не отменяет гипотезу о недоступности Railway из РФ — `/admin` без VPN всё ещё не открывался, это отдельный, реальный факт. Но объясняет **конкретный** воспроизведённый симптом «купил кота → reload → прогресс пропал» полностью, без сети. TASK-098 остаётся открытой отдельной задачей на доступность самого домена Railway — это может объяснять другую часть разрыва 32 vs 403 пользователей (например, для игроков, у которых первый же запрос вообще не проходит и `session_start` не создаётся), но не эту.
