# 📌 TASK-104: Возврат «мёртвых» сессий (`idle: true`) через VK-уведомления

> **Статус:** 🔴 Не начато
> **Приоритет:** P3
> **Зависимости:** данные `session_end.idle` (TASK-093/094) — в проде меньше суток

---

## Идея

`session_end.idle` (сессия без единого `merge`/`buy`) — теперь видимый факт. Для таких сессий можно пробовать `VKWebAppAllowNotifications` с разной задержкой по `days_since_install`, вместо одинаковой рассылки всем.

## Как делать

1. Дождаться данных: какая доля сессий `idle`, зависит ли от `days_since_install`
2. Если доля заметная — спроектировать разрешение на уведомления в подходящий момент (не сразу при первом заходе — это раздражает и понижает конверсию в разрешение)
3. Развести задержку повторного уведомления по когорте

## Критерии

- [ ] Доля `idle`-сессий посчитана
- [ ] Решение о моменте запроса разрешения на уведомления принято по данным
- [ ] Есть замер влияния на возврат (`return_session`)
