# 📌 TASK-101: Контекстный пейволл на `action_blocked` вместо статичной кнопки «Магазин»

> **Статус:** 🔴 Не начато
> **Приоритет:** P1 — первая по-настоящему data-driven монетизационная фича
> **Зависимости:** нужно накопить данных после TASK-092/093 (дедупликация и сами события `action_blocked` в проде меньше суток)

---

## Идея

`action_blocked` (TASK-093) теперь фиксирует первый момент, когда конкретный игрок упёрся — `no_coins`, `grid_full`, `no_rubies`, с `reason`/`context`/`cost`/`balance`. Вместо того чтобы просто показывать тост «Мало монет!» и ничего не предлагать — показывать микро-оффер ровно в этот момент (бесплатный кот за рекламу, скидочный голос), привязанный к тому, на чём именно споткнулись.

## Как делать

1. Дождаться недели чистых (дедуплицированных, TASK-092) данных `action_blocked` — понять реальное распределение причин отказа, не гадать заранее
2. Определить 1-2 самых частых `reason` — с них начинать, не пытаться закрыть все сразу
3. Спроектировать оффер под конкретную причину (для `no_coins` в контексте `buy_cat` — не то же самое, что для `no_rubies` в `auto_merge`)
4. Замерить `purchase_initiated` / `shop_opened` до и после — иначе непонятно, сработало ли

## Критерии

- [ ] Топ-2 причины `action_blocked` определены по данным, не предположениям
- [ ] Оффер спроектирован и задеплоен для первой причины
- [ ] Есть замер до/после по воронке магазина
