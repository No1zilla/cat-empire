## Что сделано

### Команды

```json

"test:visual:bless": "npm run build && node tests/test_visual_snapshots.js"
```

Сборка вшита в команду намеренно: сюита смотрит на `dist/`, и без пересборки легко проверить вчерашний билд и решить, что всё хорошо.

В `npm test` не добавляли — там остаётся только `tests/runAll.js`. Визуальной сюите нужен Playwright с браузерами, на чистой машине это долгая установка.

### Документация

`GEMINI.md` → «Автоматизированное тестирование»: `npm run test:visual` гонять **перед выкаткой в прод и после любых правок вёрстки или рендера** (HUD, сетка, модалки, шрифты, дизайн-токены, PixiJS). Там же предупреждение к `test:visual:bless`: перегенерация объявляет текущий вид нормой, PNG перед коммитом надо смотреть глазами.

### Мусор в `snapshots/diffs/`

Каталог был закоммичен вместе с четырьмя `failed_*.png` от давнего красного прогона. Добавлен в `.gitignore` и убран из индекса: это отладочные артефакты падения, им не место в истории.

## Решение по CI: пока **не подключаем**, гоняем руками

Причина техническая, а не организационная. Эталоны сняты в headless Chromium на macOS. Растеризация шрифтов и сглаживание на Linux-раннере GitHub Actions отличаются, и при пороге 0.1% сюита там покраснеет на ровном месте — на любом тексте. Чтобы CI имел смысл, нужен один из вариантов:

1. **Держать эталоны для Linux** — снимать их в том же контейнере, что и прогон (`mcr.microsoft.com/playwright`), и не смотреть на них с macOS. Тогда локальный `npm run test:visual` перестаёт работать без докера.
2. **Задрать порог до 2–3%** — но тогда сюита снова перестаёт ловить мелкие сдвиги, ровно то, от чего ушли в [TASK-095](../TASK-095/TASK-095.md).

Ни то, ни другое сейчас не окупается: релизы ручные, вёрстку правит один человек. Возвращаться к вопросу — когда появится второй разработчик, трогающий UI.

Если всё-таки подключать, минимальный рецепт: контейнер `mcr.microsoft.com/playwright:v1.62.0-jammy`, эталоны пересняты внутри него, шаг `npx playwright install --with-deps chromium`, и обязательно `actions/upload-artifact` на `snapshots/diffs/` — без сохранённых кадров разобрать падение в CI невозможно.
