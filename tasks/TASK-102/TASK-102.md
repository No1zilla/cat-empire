# 📌 TASK-102: Ad waterfall по фактическим отказам, а не по статичному порядку

> **Статус:** 🔴 Не начато
> **Приоритет:** P2
> **Зависимости:** нет

---

## Идея

`getNativeAdFormatOrder()` в `src/api/vkAds.js` — фиксированный порядок форматов (`interstitial`→`reward` на десктопе, наоборот на мобильном). Данные в `ads.reasons` уже показывают, что `"Requests limit reached"` кластеруется по `ad_type` и по времени у одного и того же пользователя — то есть VK временно режет конкретный формат для конкретного игрока, а мы всё равно пробуем его снова.

## Как делать

Хранить на клиенте (localStorage, TTL несколько минут) последний неудачный формат с причиной `"Requests limit reached"` для текущего игрока и пропускать его в `getNativeAdFormatOrder()`, пока не истечёт TTL — вместо повторного дорогого запроса, который заведомо провалится.

## Критерии

- [ ] Повторный запрос того же формата после `"Requests limit reached"` не уходит раньше TTL
- [ ] Fill rate по `ads.reasons` не упал (пропуск формата не должен снижать шанс на успех в других форматах)
