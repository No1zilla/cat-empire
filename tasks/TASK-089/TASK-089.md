# 📌 TASK-089: `dist/` лежит в git вопреки `.gitignore` — и уже протух

> **Статус:** ✅ Исправлено — снят с отслеживания
> **Приоритет:** P2 — риск раздать игрокам устаревшие ассеты
> **Зависимости:** [TASK-085](../TASK-085/TASK-085.md)

---

## Проблема

`.gitignore` содержит `dist` (строка 6), но `git ls-files dist` показывал **36 файлов**: правило добавили уже после того, как каталог попал в индекс, а ретроактивно игнор не действует. В итоге собранный бандл вручную перекладывался в каждый релизный коммит.

### Он реально разошёлся с исходниками

| Файл | Размер |
|---|---|
| `public/assets/cats/cat_12.png` (исходник) | 71993 б |
| `dist/assets/cats/cat_12.png` (в git) | 74875 б |

Арт кота 12 уровня обновили, а собранную версию в репозиторий не переложили. То есть закоммиченный `dist/` — не просто мусор, а **устаревший** мусор.

## Почему снимать безопасно

Оба живых воркфлоу собирают фронт сами и публикуют свой свежий результат:

```yaml
- run: npm ci
- run: PLATFORM=vk npm run build
- uses: peaceiris/actions-gh-pages@v4
  with:
    publish_dir: ./dist
```

Закоммиченный в `main` каталог `dist/` при этом не читается никем — Pages раздаётся из ветки `gh-pages`, которую наполняет CI (см. [TASK-085](../TASK-085/TASK-085.md)). Сборка на Railway (`nixpacks.toml`) тоже касается только `server/`.

## Что сделано

```bash
git rm -r --cached dist
```

Файлы остаются на диске (и пересобираются `npm run build`), но уходят из индекса. `.gitignore` уже был готов — теперь он наконец работает.
