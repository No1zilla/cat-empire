## Суть

`server/src/routes/leaderboard.js` — единственный роут, оставшийся на старом `vkAuth`
вместо `playerAuth`. Он берёт `req.vkUserId`, то есть всегда VK-ветку.

Для игрока из Telegram заголовка `x-vk-sign` нет, поэтому `vkAuth` уходит в гостевой
`999999999`. А этот id явно исключён из выборки:

```sql
WHERE vk_id IS NOT NULL AND vk_id NOT IN ('0', '999999999')
```

Значит `me` для него не вернётся никогда. При этом сами строки Telegram-игроков
(`vk_id = 'tg:4242'`) в топ попадают — они не отфильтрованы. Итог: игрок из Telegram
видит общий топ, но собственного места в нём не находит ни при каких обстоятельствах.

VK-игроков это не задевает: по [playerKey](../../server/src/utils/playerKey.js) их ключи
остались без префикса, и `vk_id = $1` для них по-прежнему совпадает.

## Что сделать

1. Перевести роут на `playerAuth`, брать `playerKey(req.player)` вместо `req.vkUserId`.
2. Проверить, что гостевой ключ по-прежнему исключается, а `tg:`-ключи — нет.
3. Тест: игрок из Telegram получает свою строку `me` с корректным рангом.
